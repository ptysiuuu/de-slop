# deslop

> Strip AI-generated writing artifacts from any text or code file.
> Fast, opinionated, zero configuration required to get value.

`deslop` is a blazingly fast CLI tool written in Rust that scans your files to identify and fix common artifacts left behind by LLMs (Large Language Models). It deterministically finds and removes typographic anomalies, prose tics, and redundant code comments without relying on any external API calls.

## Features

- **Typographic Artifacts**: Replaces rare em/en dashes, curly quotes, non-breaking spaces, and zero-width characters commonly generated by LLMs.
- **Prose Artifacts**: Strips sycophantic closers ("I hope this helps!"), filler openers ("Certainly!"), hedge clusters ("it is important to note that"), and hollow intensifiers ("utilize", "leverage").
- **Code Artifacts**: Automatically removes trivial comments that just restate the adjacent code and deletes boilerplate docstrings.
- **Emoji & Symbol Rules**: Cleans up unnecessary decorative Unicode symbols and emojis.
- **Interactive Mode**: Provides a slick terminal UI to review, apply, edit, or skip each match individually.
- **Git Integration**: Can run specifically on staged files (`--staged`) and easily installs as a pre-commit hook.
- **Custom Rules**: Easily extensible with `.deslop-rules` files to flag or fix custom phrases specific to your project or company style guide.
- **Fast**: Built in Rust with Rayon for parallel processing and SIMD-accelerated pre-scanning.

## Installation

Ensure you have Rust and Cargo installed, then clone the repository and build from source:

```sh
git clone <repository_url>
cd de-slop
cargo install --path .
```

## Usage

Simply pass a file or directory to `deslop`. It has sensible defaults and works out of the box.

```sh
# Scan and fix a single file in-place
deslop file.md

# Scan a whole directory recursively, but only show what would change (dry-run)
deslop --recursive --dry-run ./src

# Scan with an interactive prompt to approve/reject changes
deslop --interactive ./docs

# Print a unified diff to stdout instead of modifying files
deslop --diff ./src

# Scan only git-staged files
deslop --staged
```

### Options

| Flag | Description |
|---|---|
| `-r, --recursive` | Walk directories recursively |
| `-d, --dry-run` | Show what would change, write nothing |
| `--diff` | Print unified diff to stdout |
| `-i, --interactive` | Confirm each match individually |
| `-p, --profile <PROFILE>` | Rule set: `conservative`, `prose`, `code`, `aggressive` (default: `prose`) |
| `--fix <RULE>` | Enable only this rule (repeatable) |
| `--skip <RULE>` | Disable this rule (repeatable) |
| `-o, --output <PATH>` | Write to this path instead of in-place |
| `--report` | Print score summary after processing |
| `--threshold <FLOAT>` | Exit code 1 if any file exceeds N hits/1k chars |
| `--min-confidence <FLOAT>` | Skip matches below this confidence (default: 0.6) |
| `--explain` | Show reasoning for each match |
| `--format <FORMAT>` | Output format: `human`, `json` (default: `human`) |
| `--config <FILE>` | Load config from path (auto-discovered otherwise) |
| `--lang <LANG>` | Force language parsing: `py`, `js`, `rs`, `md`, `txt`, etc. |
| `--staged` | Scan git-staged files only (pre-commit mode) |
| `--init` | Write a `.desloprc.toml` for the current project |

### Exit Codes

- `0`: Clean — no matches above threshold, or dry-run with no errors
- `1`: Slop found above threshold (useful with `--threshold` in CI)
- `2`: Execution error (file not found, bad config, syntax error in rules, etc.)

## Profiles

Profiles control which rule categories are active. They build on top of each other.

- **`conservative`**: Typographic and Emoji/Symbol rules only.
- **`prose`** (Default): Includes `conservative` + Prose rules (filler openers, hedges, hollow intensifiers).
- **`code`**: Includes `conservative` + Code rules (trivial comments, docstring filler).
- **`aggressive`**: All rules active (Typographic, Symbol, Prose, and Code).

You can set the profile with `-p` or `--profile`:

```sh
deslop --profile code src/
```

## Configuration File

`deslop` automatically walks up your directory tree to find a `.desloprc.toml`, `.desloprc.yaml`, or `.desloprc.yml` file. 

You can easily generate a config file for your project using:
```sh
deslop --init
```
This detects your project type (Rust, Python, Markdown dominant, etc.) and generates an appropriate profile.

### Example `.desloprc.toml`

```toml
profile = "prose"          # conservative | prose | code | aggressive
report = true              # always print score summary
min_confidence = 0.6       # skip matches below this threshold
format = "human"           # human | json

[rules]
skip = ["ellipsis", "en-dash"]            # disable specific rules
custom_phrases = ["as mentioned above"]   # added to prose pattern matching
allow_symbols = ["✓", "→"]                # never flagged by decorative-unicode or emoji

[files]
exclude = ["vendor/**", "*.min.js", "CHANGELOG.md", "target/**"]
```

## Custom Rules

You can define your own rules in `.deslop-rules` files placed anywhere in your project. `deslop` will find and merge them automatically. Rules in deeper directories override parent rules.

### Rule Syntax

```text
rule <name>
  match: "literal" | "rege(x)" | """multiline regex"""
  fix: delete | delete-line | "replacement text" | flag
  message: "Reason shown in reports"
  confidence: 0.0-1.0
  files: "*.md, docs/**"
  severity: warn | error
```

### Examples

**Prose Style Guard:**
```text
rule no-weasel
  match: "arguably|presumably|ostensibly|purportedly"
  fix: flag
  message: "Weasel word. State the claim or cut it."
  confidence: 0.80

rule passive-voice-flip
  match: "(?i)(the (?:system|app|tool)) is (started|stopped|restarted) by"
  fix: "$1 $2s when"
  message: "Passive voice. Rewrite as active."
  confidence: 0.65
  files: "*.md"
```

**Disabling Built-in Rules:**
You can also disable built-in rules for a specific directory tree:
```text
disable em-dash
disable hollow-intensifiers
```

### Validating Custom Rules

Check your syntax using:
```sh
deslop check-rules
```
This validates all `.deslop-rules` files and reports errors before you run a full scan.

## Git Integration (Pre-commit Hook)

Keep your codebase slop-free by installing `deslop` as a pre-commit hook:

```sh
deslop install-hook
```

This adds a hook to `.git/hooks/pre-commit` that runs `deslop --staged --threshold 1.0 --format json --report` before every commit, blocking the commit if the threshold is exceeded.
